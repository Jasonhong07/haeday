# Haeday 직접 체험하기

작성: 2026-09-26. 본인 PC에서만 실행하는 로컬 체험판이다. 운영 서버에 배포한 상태가 아니다.

## 지금 바로

1. 브라우저에서 **http://127.0.0.1:3008** 을 연다. 같은 PC의 Chrome/Edge도 가능하다.
2. 상단 노란색 `LOCAL DEMO` 안내를 확인한다. 실제 돈, 외부 AI 호출, 이메일 발송은 없다.
3. `See my birth chart · Free` → 날짜·시간·도시 입력 → 검색 결과에서 도시를 선택한다.
4. 예시: **1990-05-12 / 09:30 / Seoul, South Korea**. 실제 개인정보를 넣지 않아도 된다.
5. 무료 명식에서 Day Master·오행·시간 경계 안내를 확인한다.
6. `Unlock my reading · $3.99` → `Check your birth details`에서 입력을 재확인한다. 틀리면 `Edit birth details`.
7. 데모 동의 체크 → `Continue to payment` → **`Pay $3.99 (test)`** → `Open my reading`.
8. 풀이에서 `Larger text`, 7개 목차 이동, `Share my Day Master`를 눌러본다. 공유 미리보기에는 생년월일·장소·풀이 본문이 없다.

**화면의 풀이 본문은 반복되는 테스트 문장이다.** 실제 모델의 해석 품질을 보여주는 샘플이 아니다. 명식 계산·DB 저장·권한 검사·결제 처리 함수·풀이 검증과 저장은 실제 앱 경로를 사용한다. 결제 사업자와 AI 응답만 대체한다.

## 껐다가 다시 열기

1. 파일 탐색기에서 `Desktop\Fotel\haeday` 폴더를 연다.
2. **`START_LOCAL_DEMO.cmd`를 더블클릭**한다.
3. `Ready`가 보이면 위 주소를 연다. 이 창은 사용하는 동안 열어둔다.
4. 종료할 때 해당 창에서 `Ctrl+C`를 누른다. 창을 닫아도 된다.
5. 이미 서버가 켜져 있다면 다시 시작하지 말고 주소만 연다. `port 3008 in use`는 기존 창이 실행 중이라는 뜻일 수 있다.

이미 이 작업에서 로컬 DB와 시작 파일을 설치·검증했다. 명령어 복사, DB 설치, 키 생성은 Jason이 할 필요 없다. 실행 실패 시 창의 오류 문구만 알려주면 에이전트가 해결한다. 비밀키·환경 변수는 보내지 않는다.

## 다른 기능 체험

- **시간 모름:** 새 명식 → `I don't know`. 시주가 빠지고 필요한 날짜 경계 안내가 나오는지 본다.
- **PayPal:** 새로운 명식의 결제 화면에서 동의 체크 후 `Email for your reading link`에 `demo@example.test` 입력 → `PayPal (test)`. 실제 PayPal 창·Venmo 앱은 이 데모에서 열리지 않는다.
- **내 풀이:** 홈 → `My readings`. 같은 브라우저에서 만든 주문이 보인다. 다른 브라우저는 다른 손님이므로 동일한 주문을 바로 볼 수 없다.
- **환불:** 내 풀이의 주문에서 환불 페이지로 이동한다. 로컬 가짜 결제만 반환되며 실제 돈은 움직이지 않는다.
- **이메일·로그인·관리자:** 이 데모는 메일을 보내지 않는다. 관리자 인증을 우회하는 링크도 만들지 않았다. 실제 도메인의 Resend·관리자 로그인은 staging에서 별도 확인한다.
- **휴대폰:** 이 주소는 현재 PC 전용이다. 휴대폰에서 열려면 staging URL이 필요하다. 공유기 포트 개방은 하지 않는다.

## 데이터와 한계

- 저장: `Fotel\.haeday-local`의 전용 PostgreSQL, `haeday_demo` DB. 운영 DB와 연결하지 않는다.
- 테스트 DB `haeday_test`는 자동 테스트용으로 반복 초기화되며 데모 주문과 분리된다.
- 출생정보는 데모에서도 앱의 암호화 경로로 저장한다. 로컬 암호화 키는 `.haeday-local`에만 있으며 Git에 넣지 않는다.
- PC 재시작 시 H: 임시 경로를 시작 스크립트가 다시 연결한다. 다른 H: 드라이브가 있으면 덮어쓰지 않고 중단한다.
- 가짜 결제 세션은 서버 메모리에 있다. 결제창을 열고 서버를 재시작하면 세션이 사라질 수 있다. 이때 새 명식을 만들어 다시 체험한다. 이미 생성한 풀이·주문은 DB에 남는다.
- 실서비스의 카드/지갑/PayPal SDK·웹훅·메일 도착·환불 정산을 검증한 증거로 이 데모를 쓰지 않는다.
