| D26 | EoT method: NOAA solar calculator (Meeus) formulation instead of the short NOAA approximation. Max difference vs Skyfield across fixtures 11.8 s (tolerance 30 s) | proposed (implementation detail) |
| D27 | City data (M1): GeoNames cities15000 (34,149 rows → 34,126 after merging 23 same-name duplicates within 50 km) bundled as `data/cities.json`, built by `pnpm places:build`. Region names: GeoNames admin1 file is unreachable from our build network, so names are derived once from reverse_geocoder 1.5.1's GeoNames-derived table (`tools/places/derive_admin1.py` → `data/admin1_names.json`); US shows the state postal code. Labels "City, Region, Country"; if still ambiguous, "(near X)" or "(N km from X)". Region names are display only and never reach the engine. placeId = `gn:<geonameId>`; the server resolves lat/lon/tz; the API never returns coordinates. Aliases: NYC, LA, SF, DC, Philly. Towns under 15,000 people are not listed (customer picks the nearest listed city; true-solar effect ≈ 4 min per 1° of longitude) | proposed (implementation detail) |
| D28 | **Equation of time (균시차) in the solar clock.** Current policy (D09/D26): true apparent solar time = longitude correction + EoT. 포스텔러 (Korea's most used 만세력) uses 지역시 = longitude correction only, no EoT; with EoT removed we match 포스텔러 on 10/10 crosscheck cases (now 9/10). Impact measured on 20,000 random births: hour pillar differs in 5.9%, day pillar in 0.56%. Options: (A) keep EoT (astronomically "true" solar time), (B) drop EoT to match 포스텔러 and most Korean apps. Agent recommends B | proposed (Jason decides) |
| D29 | Date-line moves (Samoa 2011, Kwajalein 1993): the solar clock is anchored to the civil offset actually in use, `offset + wrap180(lon − offset/4)·4`, which equals the spec formula whenever both are within ±12 h and needs no DST guess. The audit-only standard offset uses a both-sides DST test with ±3/6/9/12-month probes and ignores offsets > 3 h away. Also fixed (found by the reviewing AI): January 1900 year lookup, skipped civil date with unknown time → `nonexistent_local_time`. New fixtures F32–F37; oracle EoT tolerance 60 s (1900 needs 44 s) | proposed (implementation detail, no policy change) |
