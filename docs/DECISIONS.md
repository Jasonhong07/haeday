Region names: GeoNames admin1 file is unreachable from our build network, so names are derived once from reverse_geocoder 1.5.1's GeoNames-derived table (`tools/places/derive_admin1.py` → `data/admin1_names.json`); US shows the state postal code. | D28 | **Equation of time (균시차) in the solar clock.** Current policy (D09/D26): true apparent solar time = longitude correction + EoT. 포스텔러 (Korea's most used 만세력) uses 지역시 = longitude correction only, no EoT; with EoT removed we match 포스텔러 on 10/10 crosscheck cases (now 9/10). Impact measured on 20,000 random births: hour pillar differs in 5.9%, day pillar in 0.56%. Options: (A) keep EoT (astronomically "true" solar time), (B) drop EoT to match 포스텔러 and most Korean apps. Agent recommends B. **Jason chose B (2026-09-24, "균시차는 제거하자")** → policy `haeday-chart-v2`, 포스텔러 10/10 | accepted (Jason 2026-09-24) |
| D29 | Date-line moves (Samoa 2011, Kwajalein 1993): the solar clock is anchored to the civil offset actually in use, `offset + wrap180(lon − offset/4)·4`, which equals the spec formula whenever both are within ±12 h and needs no DST guess. The audit-only standard offset uses a both-sides DST test with ±3/6/9/12-month probes and ignores offsets > 3 h away. Also fixed (found by the reviewing AI): January 1900 year lookup, skipped civil date with unknown time → `nonexistent_local_time`.
